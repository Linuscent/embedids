Now a Zephyr RTOS module

Add intrusion detection to Zephyr firmware with a few Kconfig lines. Threads and interrupts submit samples without blocking; one detector thread checks each one.

  • ≤ 120 ms from trigger to alert in every simulated attack scenario
  • No heap allocation in the detector or the queue adapter
  • 19 / 19 tests passing on native_sim with Zephyr v4.2.0
Integration guide Read the case study

Overview

An open-source intrusion detection library that runs on the device, offline, in memory you allocate.

Product Features

Open-Source SDK (Apache 2.0 Licensed)

One C11 library. You provide the buffers; it checks every sample against your rules.

  • No heap allocation
  • Threshold rules
  • Custom algorithms
  • CMake package
  • Zephyr module

Key Features

On-Device Intelligence

  • Detection runs on the device, with no cloud dependency
  • Fixed history buffers that you allocate

Customizable Security

  • Your own metrics and thresholds
  • Custom detection functions beside the built-in rules

Developer-Friendly Design

  • CMake package, FetchContent or Zephyr module
  • Examples, a tutorial and automated tests

Why EmbedIDS?

  1. Tight memory and power budgetsFixed memory, no heap allocation
  2. Unreliable connectivityDetection runs offline, on the device
  3. Fleet-scale costsOpen source, with no licence fees
  4. Diverse hardwarePortable C11 core, Linux agent and Zephyr module

  1. Add EmbedIDS with CMake, or as a Zephyr module
  2. Describe each metric and the rule that guards it
  3. Feed samples and act on the alerts
